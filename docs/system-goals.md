# 系统目标与持续优化方向

本文档记录「拾光纪」的长期产品目标，用于指导后续功能设计、数据模型和算法优化。

## 1. 持续追踪新闻事件

系统的核心不是只展示一条新闻，而是追踪一个新闻事件从发生到后续发展的完整过程。

目标：

- 把多篇报道聚类成同一个事件，避免用户看到大量重复新闻。
- 记录事件现在发生了什么，以及之后又发生了什么。
- 将事件的发展过程串成清晰的时间线，帮助用户理解来龙去脉。
- 对已追踪事件持续补采新报道，识别新的进展、结果、影响和争议。

理想效果：

用户关注某个事件后，不需要自己反复搜索。系统应该持续告诉用户：

- 这个事件最新进展是什么。
- 相比上次查看发生了哪些变化。
- 关键节点按时间顺序如何演化。
- 哪些来源报道了这件事，信息是否仍在变化。

## 2. 对新闻进行多维度分类

同一个新闻事件可能同时属于多个主题，不应该只能被归到单一分类。

例如：

- 一条新闻既是 `AI` 相关，也和 `医学` 有关。
- 一条新闻既是 `财经` 相关，也和 `科技公司` 有关。
- 一条新闻既是 `冲突` 相关，也可能影响 `能源` 或 `经济`。

目标：

- 根据新闻标题、摘要、来源文章和后续报道，为事件打上多个主题标签。
- 每个标签都应有置信度和推荐原因，说明为什么被归到这个主题。
- 分类结果应服务于用户关注，而不是只用于后台展示。
- 用户可以按自己感兴趣的标签重点关注新闻事件。

## 3. 用户关注方式

用户关注的对象可以有两类：

- 具体事件：用户明确关注某个新闻事件，系统持续追踪它的发展。
- 兴趣标签：用户关注某类主题，例如 `AI`、`医学`、`地震`、`半导体`，系统自动推荐相关事件。

关键词输入只是用户表达兴趣的一种方式。系统底层应尽量把用户输入归一化为主题标签，而不是简单做字符串匹配。

例如：

- 用户输入 `ai`，应理解为 `人工智能` 主题。
- 用户输入 `大模型`，也应归到 `人工智能` 主题。
- 用户输入 `医学 AI`，可能同时关联 `人工智能` 和 `医学`。

## 4. 分类与推荐原则

推荐给用户的新闻应优先使用**向量语义召回**（基于事件标题 embedding），主题分类作为增强与兜底。

分层说明：

- **Embedding 层**：将事件标题与用户关键词转为向量，用余弦相似度做语义匹配；不依赖标题字面包含。
- **DeepSeek 分类层**：为事件打多维主题标签、生成置信度与推荐原因；可开关，属于付费增强。
- **规则兜底**：自由中文关键词的文本包含、英文词边界匹配等，在 embedding 不可用或未命中时使用。

需要避免：

- `ai` 误命中 `trillionaire`、`said` 这类单词内部。
- 只因为标题出现某个字面词，就把无关新闻推荐给用户。
- 只给出结果，不解释为什么这条新闻会被推荐。

推荐结果应尽量包含：

- 语义相似度（向量命中时）。
- 命中的主题标签与分类置信度（有分类结果时）。
- 推荐原因，例如「标题涉及医疗影像模型」。
- 如果是多维事件，应展示多个相关标签。

## 5. 持续优化方向

后续优化应围绕以下方向推进：

- 提升事件聚类质量，让同一事件的不同报道尽量合并到一起。
- 提升时间线生成质量，让事件发展过程更清晰。
- 扩展主题标签体系，支持更多可订阅维度。
- 使用 DeepSeek 等模型对事件进行语义分类，减少关键词误匹配。
- 使用本地或远程 embedding 模型做标题级向量召回，提升关键词关注的语义相关性。
- 保留规则匹配作为兜底，但推荐逻辑应优先使用向量相似度，其次分类结果。
- 为每次推荐提供可解释原因，方便用户判断是否相关。
- 根据用户反馈持续调整标签体系、分类 prompt 和置信度阈值。
